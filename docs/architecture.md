# Architecture

`src/domain` is the persistent music model, validation, commands, time conversion, sampler-zone selection, and offline DSP. `src/audio` adapts a validated immutable project snapshot to Web Audio scheduling, recording, sample playback, and lazy-loaded SoundFont synthesis. `src/store` owns command history and derived UI state. React surfaces dispatch domain commands and never mutate project objects.

The Electron main process owns native windows and filesystem operations. Saves write a temporary sibling then rename it. Autosave writes to Electron user data and is never substituted silently for the user's project. The isolated preload bridge exposes typed project, audio-asset, instrument-library, ACE-Step, and Seed-VC calls. Imported/recorded audio is normalized to PCM16 WAV, hashed with SHA-256, atomically stored once, and resolved lazily for playback/export. Instrument and optional-provider downloads run only in the main process; manifests, samples, runtimes, and models are stored once outside project files. Seed-VC installs a minimal singing-inference dependency profile with an explicitly pinned CUDA PyTorch build, commits its manifest only after runtime verification, and cleans temporary package caches. Conversion requires an explicit voice-rights confirmation and stops ACE-Step first to bound GPU-memory use.

Live scheduling runs a small look-ahead timer on the renderer control plane. Oscillators, gains, filters, delay nodes, and decoded buffers are constructed before their scheduled start; Chromium owns real-time processing. Structural project mutation never occurs in an audio callback. Queue overflow is contained by limiting scheduling to one horizon and deduplicating event keys.

Agent mode is a separate local STDIO process. `mcp/server.ts` publishes focused tools; `mcp/workspace.ts` confines project/output paths, checks optimistic revisions, snapshots history, and performs atomic replacement; `mcp/music.ts` maps validated tool inputs onto the same domain types and renderer used by the UI. Long ACE-Step and Seed-VC operations are persisted as job records and split into submit, status, collect, and abandon requests. Seed-VC runs in an isolated detached worker so conversion survives an MCP request timeout or client reconnect; inputs remain workspace-confined and collected WAVs are written atomically through the same workspace boundary. The installed app packages this server inside `app.asar`; client configurations launch the Resonant executable with `ELECTRON_RUN_AS_NODE=1`, so the same tested runtime works without a system Node dependency. MCP uses the same content-addressed audio library and has read-only access to the shared instrument library so it can list and render installed SoundFonts, but cannot install packs, capture microphones, run arbitrary commands, or control unsaved desktop state. Electron watches an open project's directory and forwards valid external content to the renderer, where dirty in-app state requires explicit confirmation before reload.

Musical time is floating-point quarter-note beats. A 4/4 bar is four beats; a 16-step clip spans four beats. Conversions use `seconds = beats * 60 / bpm`; exports round sample positions to the nearest integer. Live loop boundaries and export use the same step-index rules.
